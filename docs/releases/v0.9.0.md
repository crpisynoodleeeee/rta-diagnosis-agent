# v0.9.0 - Server-side Staging Read-only Prep

Status: Released on 2026-08-28

## Summary

V0.9 prepares server-side, read-only Staging integration for the RTA Diagnosis Agent without touching a real environment. This phase locks down three contracts — the field-mapping baseline, the Staging Adapter design (including the replay sample format) and the security/audit/monitoring design — and ships replay samples, server-side modules (staging adapter, security, audit, monitor) and an offline validation aggregator with all five groups passing (32/32).

## Added

- Contract trio (`docs/architecture/v0.9-*.md`):
  - [V0.9 字段映射基线](docs/architecture/v0.9-field-mapping-baseline.md): normalized field mapping based on the V0.8 `MediaDataProvider` contract; real upstream field names and value ranges are pending external verification and are not invented at this stage.
  - [V0.9 Staging 只读 Adapter 设计](docs/architecture/v0.9-staging-adapter-design.md): component boundaries, replay sample format and authorization prerequisites for the server-side read-only Adapter.
  - [V0.9 安全、审计与监控设计](docs/architecture/v0.9-security-audit-design.md): credential handling, desensitization, audit and monitoring schema with P2 acceptance criteria.
- Replay samples and a validation aggregator skeleton for the read-only Staging path.
- Server-side modules under development: staging adapter, security, audit, monitor.
- `server/_verify_v09.cjs` acceptance skeleton running in five groups: contract / adapter / security / audit / llm-tools.

## Boundaries

- Real Staging integration is only authorized after API documentation, field-mapping verification, desensitized replay samples and test credentials/permissions are provided, and Staging access is explicitly approved.
- No production API, production credential or real company/customer/campaign data is included.
- No write operation is introduced: budget, bid, strategy, experiment or media configuration writes remain forbidden (`capabilities.readOnly = true`).
- Credentials are read from environment variables only; they are never written to files, committed to the repository or logged.

## Validation

V0.9 verification: 32/32 passed (contract 6 / adapter 8 / security 6 / audit 6 / llm-tools 6), all offline with synthetic Mock/Replay data.

The V0.8 six validation groups remain green after merging: Golden Case 7/7, Scenarios 5/5, LLM path 10/10, Assistant 47/47, V0.7 query layer 30/30, V0.8 Provider 34/34.

Real Staging integration remains pending authorization (API documentation, field-mapping verification, test credentials/permissions and explicit Staging approval).
