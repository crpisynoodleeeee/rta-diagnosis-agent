# V1.0 专项验收用例

本清单对应方案 §6.5 封版八条。除特别注明外，所有数据来自 Mock/Replay，时间线和结果可在界面及审计查询中查看。标注“必须实现”的用例要求最小纵向实现；“设计/测试为主”只要求契约、离线测试或可复现模拟，不要求生产级基础设施。

## AC-01 诊断证据可追溯（必须实现）

**Mock 数据：** `tenant-a`、任务 `task-a-001`、规则 `D12`、指标 `successRate=0.92`、合法证据 `EV-MOCK-001`。

**前置条件：** 以 `optimizer` 登录，证据新鲜且无冲突。

**步骤：** 打开任务诊断；查看规则、指标和证据；确认诊断；查看审计事件。

**期望：** 结论展示 `ruleIds`、`metricRefs`、`EV-MOCK-001`；确认成功；审计含 `view_evidence`、`confirm_diagnosis` 及前后状态；不存在未引用证据的确定性结论。

## AC-02 数据不足/过期/冲突安全降级（必须实现）

**Mock 数据：** 分别回放缺失 `groups` 的 `partial` 样本、超过 freshness 阈值的 `expired` 样本、指标与证据矛盾的 `partial` 冲突样本，以及 `timeout` 样本。

**前置条件：** 任务可读取，未创建可执行草稿。

**步骤：** 依次触发诊断并尝试确认和提交草稿。

**期望：** 展示契约中的降级枚举、文案和下一步建议；不生成确定性结论，不允许确认/提交；审计记录 `degraded` 或失败原因。

## AC-03 人工审批与零写接口（必须实现）

**Mock 数据：** 合法 `ActionDraft`，含 `diff`、指标、回滚条件和 `EV-MOCK-001`。

**前置条件：** `optimizer` 已确认诊断并提交草稿；没有真实凭证或写 API。

**步骤：** 以优化师尝试批准和执行；以审批人批准；记录一次人工/模拟执行。

**期望：** 优化师批准被拒绝并留痕；审批后状态为 `approved`；执行仅产生 `execution_recorded`/`observing` 事件，不发送任何预算、出价、策略或媒体写请求。

## AC-04 越权与跨租户拒绝（必须实现）

**Mock 数据：** `tenant-a` 的 `task-a-001`、`tenant-b` 的同结构任务；observer、optimizer、approver 三个会话。

**前置条件：** 各会话均带服务端注入 `tenantId`。

**步骤：** observer 尝试确认/建稿/审批/执行；optimizer 尝试审批；tenant-a 会话读取或修改 tenant-b 任务。

**期望：** UI 与服务/领域层均返回 DENY；无状态变化；每次拒绝均产生 `permission_denied` 或 `cross_tenant_denied` 审计事件，包含 operator、role、taskId 和结果。

## AC-05 审计时间线可见且可查询（必须实现）

**Mock 数据：** 完整闭环任务，包含所有标准事件。

**前置条件：** 至少完成发现、诊断、证据查看、确认、建稿、提交、审批、执行、观察、复盘中的一部分。

**步骤：** 按 taskId 查询；再按 operator 和 role 过滤；检查顺序与状态前后值。

**期望：** 返回 schema `{taskId, action, operator, role, timestamp, beforeStatus, afterStatus, evidenceIds, result}`；时间线按时间稳定排序；过滤结果不泄露其他租户事件。

## AC-06 执行记录进入观察和复盘（必须实现）

**Mock 数据：** 已批准草稿，观察周期 `24h`，合成回流指标。

**前置条件：** 草稿处于 `approved`，执行者为 optimizer，未调用写接口。

**步骤：** 记录人工执行；回放观察数据；提交复盘；关闭已复盘草稿。

**期望：** 状态严格经过 `execution_recorded` -> `observing` -> `reviewed` -> `closed`；每一步有审计事件；复盘展示合成数据，不宣称业务收益。

## AC-07 V1.0 专项与既有回归（必须实现 + 设计/测试为主）

**Mock 数据：** AC-01 至 AC-06 全部样本，另保留现有 V0.8/V0.9 fixtures。

**前置条件：** V1.0 专项测试已接入测试入口。

**步骤：** 执行全部 V1.0 专项用例，并执行既有七组验收/回归测试。

**期望：** V1.0 专项全部通过；既有七组保持全绿；不得因新增治理状态破坏 `current_rta_only`、EV-* 校验或只读 Provider 边界。新增限流/熔断/重试/密钥轮换仅需离线状态测试。

## AC-08 Mock/Replay 与能力边界声明（设计/测试为主）

**Mock 数据：** Mock/Replay 标识、空真实凭证环境、写接口调用计数器为 0、合成收益字段。

**前置条件：** 运行文档和离线测试审查。

**步骤：** 检查 README/契约/验收说明、环境变量边界、网络/写接口桩；搜索真实 token、媒体写调用和收益承诺。

**期望：** 文档明确 Mock/Replay、零真实凭证、无真实写接口、未验证业务收益；凭证值不进入客户端、Git、fixture 或审计；生产不可篡改仅作为哈希链/签名/外部锚定设计，不被表述为 Mock 已具备能力。
