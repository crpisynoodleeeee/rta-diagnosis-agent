# V0.9 安全、审计与监控设计

## 1. 范围

本文定义 V0.9 服务端 Staging 只读 Adapter 的安全、脱敏、审计、监控 schema 和 P2 验收标准。本期仅锁定设计，不实现生产级认证、多租户、监控系统或 Staging 联调。

安全不变量：只读、单 RTA、`current_rta_only`、服务端持凭证、最小权限、默认拒绝、日志不含秘密、真实数据不进入公开 Demo/仓库。

## 2. 凭证管理

### 2.1 环境变量注入

复用 `demo/v6/llm-proxy.mjs` 的 `DEEPSEEK_API_KEY` 模式：进程启动时从 env 读取，缺失即拒绝调用；发送上游请求时才注入 `Authorization`，不落文件、不进仓库、不回传前端、不写日志。

V0.9 变量命名锁定如下（值均不得提交）：

| 变量 | 用途 | 约束 |
| --- | --- | --- |
| `STAGING_API_BASE_URL` | Staging API 基址 | 仅允许 HTTPS 和批准的主机白名单；禁止携带 userinfo/query 凭证 |
| `STAGING_API_TOKEN` | Bearer Token | 必填；只由服务端读取；不得打印长度以外的信息 |
| `STAGING_PROVIDER_ID` | Provider 稳定标识 | 非秘密；审计用，如 `staging-v09` |
| `STAGING_PLATFORM` | 媒体规范化代码 | 非秘密；须与字段映射表枚举一致 |
| `STAGING_HTTP_TIMEOUT_MS` | 单次 attempt 上限 | 正整数且受代码硬上限约束 |
| `STAGING_OVERALL_TIMEOUT_MS` | Provider 调用总上限 | 大于等于 attempt 上限；覆盖重试与分页 |
| `STAGING_MAX_CONCURRENCY` | 本地并发上限 | 正整数；不得用 0 表示无限 |
| `STAGING_RATE_LIMIT_RPS` | 本地速率上限 | 正数；不得超过上游批准配额 |
| `STAGING_MAX_RETRIES` | 白名单错误最大重试次数 | 非负整数；仅适用于 3 类 retryable 错误 |

环境变量名称可以存在日志/文档，值不可以。测试必须使用占位 Token，不得使用真实 Staging 凭证。

### 2.2 最小权限矩阵

| 主体 | 当前 RTA 配置 | 当前 RTA 指标/趋势 | 当前 RTA 组/变更 | 回传聚合 | 跨 RTA/账户全局 | 写预算/出价/策略/实验 | 凭证读取 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Staging 服务账号 | 读 | 读 | 读 | 读（仅聚合） | 禁止 | 禁止 | 不适用 |
| 服务端 Adapter 进程 | 通过服务账号读 | 通过服务账号读 | 通过服务账号读 | 通过服务账号读 | 请求校验拒绝 | 无方法、无权限 | 仅进程 env |
| 规则引擎 / 查询工具 | 读规范化结果 | 读规范化结果 | 读规范化结果 | 读规范化结果 | 禁止 | 禁止 | 禁止 |
| 浏览器 / GitHub Pages | 仅离线 Mock/Replay | 仅离线 Mock/Replay | 仅离线 Mock/Replay | 仅离线 Mock/Replay | 禁止 | 禁止 | 禁止 |
| 运维人员 | 按职责查看脱敏状态 | 按职责查看脱敏状态 | 按职责查看脱敏状态 | 按职责查看脱敏状态 | 默认禁止 | 默认禁止 | 仅授权轮换平台，不得查看应用日志取值 |

真实授权应限制到批准租户、账户和 RTA 白名单；若上游无法提供资源级只读 scope，则不得以高权限 Token 替代进入联调。

### 2.3 Token 轮换与过期流程

1. 负责人在受控密钥系统申请新的只读 Token，核对 scope、租户/账户/RTA 白名单和过期时间。
2. 在 Staging 环境更新 `STAGING_API_TOKEN`；旧值不经聊天、工单正文、代码或日志传递。
3. 重启/滚动替换 Adapter 进程，使其重新读取 env；禁止运行时把 Token 暴露为管理 API。
4. 用最小只读探针验证：一次允许的当前 RTA 查询成功、一次越权范围查询被拒绝、审计日志无凭证。
5. 观察权限失败、成功率和数据质量指标；确认新 Token 工作后撤销旧 Token。
6. 记录轮换人、时间、凭证版本指纹（不可逆短指纹）、scope 和验证结果，不记录 Token。

收到 401/明确过期业务码时映射 `AUTH_REQUIRED`、不自动重试并告警；403 映射 `PERMISSION_DENIED`，先核对 scope 而非反复换 Token。紧急泄露时立即撤销、轮换、停止受影响实例、审查审计记录并按事件流程处理。

## 3. 脱敏设计

脱敏发生在日志/监控/错误输出/回放样本落盘之前；Provider 内部规范化数据仍按最小业务需要保留，但不得进入公开前端。固定盐哈希仅用于同一受控环境内关联，不得使用可逆加密替代展示 masking。

| 分类 | 字段/路径示例 | masking 规则 |
| --- | --- | --- |
| 账户 | `accountId`、`advertiserId` | 保留前 2 后 2，其余 `*`；长度小于 6 时全部 `*`；审计优先保存带环境盐的 `sha256:<前12位>` |
| 账户 | `accountName`、`agencyName` | 默认全掩码为 `[MASKED_ACCOUNT]` / `[MASKED_AGENCY]`，不保留品牌词 |
| 用户 | 手机号、OAID、IDFA、CAID、IMEI、设备 ID | 日志、错误、样本中禁止原值；需要关联时仅环境盐哈希，空值仅记录 `present=false` |
| 用户 | `operator` / 操作人 | 显示首字符加 `***` 或环境盐哈希；服务账号使用稳定角色名，不记录邮箱/手机号 |
| 广告 | 项目、计划、单元、创意、策略、实验名称/ID | 名称替换为对象类型加短哈希；ID 保留前 2 后 2或短哈希；公开样本全部合成 |
| 广告 | `rtaId` | 业务 Envelope 可保留当前 RTA；审计用短哈希/脱敏 ID，错误消息不得回显未经授权的原值 |
| 广告 | `bidUrl`、完整请求 URL | 仅保留批准 host + path 模板；移除 query、fragment、userinfo；日志不得记录完整 URL |
| 预算 | `dailyBudget`、`actualCost`、`controlGroupCost`、`treatmentGroupCost`、CPA/CPC | 业务计算可使用原值；日志默认不记录。必须观测时用区间桶（如 `[1000,5000)`）或比例，不记录精确金额 |
| 凭证 | Authorization、Token、SecretKey、Cookie、签名串 | 无条件删除，禁止部分保留或哈希；错误体递归清洗同名/变体键 |

脱敏函数须覆盖大小写、snake_case/camelCase 和嵌套对象；未知键采用 allowlist 输出，不采用仅 denylist 的“尽量删除”。

## 4. 审计条目 schema

每次 Provider 方法调用写一条 UTF-8 JSON 行（JSONL）。条目恰好承载以下 8 个业务字段；日志平台的采集元数据不算业务字段，也不得改变 schema。

| 字段 | 含义 | 类型/约束 |
| --- | --- | --- |
| `caller` | 调用方 | `string`，认证后的服务角色/组件名，不用自由输入用户标识 |
| `provider` | Provider | `string`，对应 `providerId`，如 `staging-v09` |
| `interface` | 接口 | 枚举：`getConfigSnapshot` / `getMetricBundle` / `getDataEnvelope` |
| `rta` | RTA | `string`，环境盐短哈希或合成测试 ID，不记真实明文 |
| `time` | 时间 | ISO 8601 UTC 字符串，调用开始时间 |
| `durationMs` | 耗时 | 非负整数，包含排队、分页与重试总耗时 |
| `result` | 结果 | 枚举：`success` / `stale` / `partial` / `insufficient` / `failure` |
| `errorType` | 错误类型 | 成功/质量降级为 `null`；失败为 12 类 ProviderError 之一 |

示例（单行）：

```json
{"caller":"readonly-tools","provider":"staging-v09","interface":"getDataEnvelope","rta":"sha256:8f25a30d41c2","time":"2026-08-28T06:30:00.000Z","durationMs":184,"result":"partial","errorType":null}
```

规则：失败也必须记录；不得记录请求/响应正文、Header、Token、账户/用户明文或精确预算；写日志失败不得把敏感原文回退到 stderr。日志访问按最小权限控制，保留期与删除策略待组织安全规范确认。

## 5. 监控指标

所有指标维度限定为低基数 allowlist：`provider`、`interface`、`platform`、`result`、`errorType`；禁止以 RTA、账户、用户、requestId、URL 作为 metric label。

| 类别 | 指标定义 | 建议类型 | 记录方式 |
| --- | --- | --- | --- |
| 成功率 | `success` 调用数 / 全部终态调用数；另报 usable rate=`success+partial` / 全部 | counter 派生比例 | `provider_calls_total{result}`；窗口和目标阈值待 Staging SLA 核验 |
| 延迟 | Provider 完整调用耗时（含排队、分页、重试） | histogram | `provider_duration_ms`，报告 P50/P95/P99；bucket 待压测锁定 |
| 超时 | `ProviderError.code=TIMEOUT` 调用数及占比 | counter | `provider_errors_total{errorType="TIMEOUT"}`；可另记脱敏 trace 中的 phase，不做高基数 label |
| 限流 | 每次 429/限流业务码、重试及最终 `RATE_LIMITED` | counter | `provider_rate_limited_total`、`provider_retries_total{errorType="RATE_LIMITED"}` |
| 权限失败 | `AUTH_REQUIRED` 与 `PERMISSION_DENIED` 分开计数 | counter | `provider_errors_total{errorType}`；突增触发安全/凭证告警，不自动重试 |
| 数据质量 | `ok` / `stale` / `partial` / `insufficient` / `failure` 终态及缺失字段数量 | counter / histogram | `provider_quality_total{result}`、`provider_missing_fields_count`；字段路径仅进脱敏 trace/审计扩展存储，不作 label |

### 5.1 stale / partial / insufficient / failure 可观测语义

| 状态 | Envelope | 审计 `result` | 监控 | 错误 |
| --- | --- | --- | --- | --- |
| `stale` | 可返回且 `meta.qualityStatus=stale`，或严格策略下不返回 | `stale` | `provider_quality_total{result="stale"}` | 严格策略为 `DATA_STALE`，否则 `errorType=null` |
| `partial` | 返回，`meta.qualityStatus=partial` 且 `missingFields[]` 非空 | `partial` | `provider_quality_total{result="partial"}` + 缺失数量 | `errorType=null` |
| `insufficient` | 不返回成功 Envelope | `insufficient` | `provider_quality_total{result="insufficient"}` | `DATA_INSUFFICIENT` |
| `failure` | 不返回成功 Envelope | `failure` | `provider_quality_total{result="failure"}` + 对应错误计数 | 除 `DATA_INSUFFICIENT` 外的既有 ProviderError |

正常完整结果记 `success`，Envelope 的 `meta.qualityStatus=ok`。同一次调用只记一个终态，重试 attempt 另记计数但不重复计终态。

## 6. 租户隔离与权限边界（初步）

> **初步设计：本期不实现。** 最终方案必须结合真实身份系统、上游授权模型和安全评审后锁定。

- 调用方身份先映射为 `tenantId + allowedRtaIds`，再进入 Adapter；客户端传入的 tenant/account 字段不作为授权依据。
- 请求仍只允许一个 `rtaId`；服务端在任何上游调用前校验该 RTA 属于调用方允许集合，默认拒绝。
- Provider 实例、限流器、缓存键和审计上下文至少按 `tenantId + providerId + credential identity` 隔离；禁止跨租户缓存命中。
- 每租户使用独立只读凭证优先；若上游只能共享凭证，必须增加服务端资源 allowlist，且在安全评审前不得投入真实数据联调。
- 未授权资源统一返回 `PERMISSION_DENIED`，避免通过 `NOT_FOUND`、耗时或错误体枚举他租户资源。
- 管理面（凭证、allowlist、轮换）与数据面（只读查询）分离；不存在任何写媒体配置的数据面方法。
- 跨 RTA、账户全局、生产环境、行业基准查询继续越界；租户隔离设计不扩大产品范围。

## 7. P2 验收标准：`server/_verify_v09.cjs`

P2 实现一个离线可重复的验证入口，按以下 5 组输出各测试名和通过/失败；任何组失败均不得宣称 V0.9 准备完成。测试不得访问生产数据。

### 7.1 `contract`

| 测试名 | 断言要点 |
| --- | --- |
| `contract/three-methods` | Staging Adapter 实现且只暴露契约要求的 3 个数据方法；能力声明 `readOnly=true` |
| `contract/current-rta-only` | 单 `rtaId` + 显式合法 `timeRange` 可通过；跨 RTA、账户级或非 `current_rta_only` 请求为 `INVALID_REQUEST` |
| `contract/envelope-v08` | `contractVersion` 与 `meta.schemaVersion` 均为 `0.8`；必填 meta 完整，Envelope 通过 V0.8 校验 |
| `contract/normalized-fields` | `ConfigSnapshot` / `MetricBundle` 字段路径、比例、金额、耗时和时间类型符合字段基线 |
| `contract/no-write-capability` | 不存在预算、出价、策略、实验或媒体配置写方法；请求过程只使用只读 HTTP endpoint |
| `contract/error-code-closed-set` | 所有失败只产生锁定的 12 类 ProviderError，不出现第 13 类错误码 |

### 7.2 `adapter`

| 测试名 | 断言要点 |
| --- | --- |
| `adapter/auth-env-injection` | Token 只从 `STAGING_API_TOKEN` 读取并在发送点注入 Authorization；请求/输出/日志不含 Token；缺失为 `AUTH_REQUIRED` |
| `adapter/pagination-bounded` | cursor/page/offset fixture 按配置遍历；重复 cursor、`maxPages`、`maxRecords`、deadline 均可终止且不会伪装完整结果 |
| `adapter/rate-concurrency-limit` | 并发和速率上限生效，三个方法共享门控，不出现无界排队 |
| `adapter/abort-timeout` | attempt/overall 超时均触发 AbortController 中止并映射 `TIMEOUT` |
| `adapter/retry-whitelist` | 仅 `RATE_LIMITED` / `TIMEOUT` / `UPSTREAM_UNAVAILABLE` 重试，次数有界并带退避；401/403/schema 不重试 |
| `adapter/http-error-mapping` | 401/403/404/429/502/503/超时及非法响应按 1b 映射到既有错误码和正确 retryable |
| `adapter/replay-eight-scenarios` | 8 类命名样本均符合 schema，并分别验证 normal/empty/latency/permission/rate/timeout/missing/error 行为 |
| `adapter/demo-dual-track` | 服务端 Adapter 不导入或修改 `demo/v6`；离线 Mock/Replay 既有行为与 Golden Case 数值不变 |

| --- | --- |

### 7.4 `audit`

| 测试名 | 断言要点 |
| --- | --- |

### 7.5 `llm-tools`

本组使用 **stub LLM + Mock/Replay 离线实现**，不依赖 Staging 授权、不读取 `STAGING_*` 凭证、不发真实网络请求。

| 测试名 | 断言要点 |
| --- | --- |
| `llm-tools/offline-only` | 网络被禁用时整组仍通过；Provider 仅为 Mock/Replay，LLM 仅为确定性 stub |
| `llm-tools/current-rta-scope` | 指标、趋势、组间、配置变更和证据查询均限制在当前 RTA，拒绝跨 RTA/账户级问题 |
| `llm-tools/evidence-grounding` | 回答只引用 QueryContext 中存在的 `EV-*`，stub LLM 不编造指标或证据 |
| `llm-tools/quality-refusal` | stale、partial、insufficient、failure 分别产生结构化说明/拒绝，不用猜测值补齐 |
| `llm-tools/provider-media-agnostic` | 同一规范化 Envelope 经 Mock 与 Replay 得到等价工具结果；回答层不出现上游 HTTP/媒体专有字段 |
| `llm-tools/golden-case-locked` | 准入门槛 `40%→80%`、参竞率 `60%→10%`、建议 `80%→60%` 原样通过 |

除新增用例外，P2 必须继续运行并保持 V0.8 及其前序验收全绿；本设计不授权修改 Golden Case 标准答案。
