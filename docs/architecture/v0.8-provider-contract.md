# V0.8 MediaDataProvider Contract

## 1. Goal

V0.8 separates data access from diagnosis logic. Mock data and future media API data must enter the rule engine and assistant through the same read-only contract.

```text
Mock records / replay samples / media API
                  |
              Adapter
                  |
         MediaDataProvider
                  |
       ConfigSnapshot + MetricBundle
                  |
       rules -> scenario -> QueryContext
                  |
      evidence-constrained assistant
```

V0.8 does not connect production accounts and does not introduce budget, bid or strategy write operations.

## 2. Provider Boundary

Every provider implements three methods:

| Method | Output | Responsibility |
| --- | --- | --- |
| `getConfigSnapshot(request)` | `ConfigSnapshot` | Current RTA configuration, experiment, groups and changes |
| `getMetricBundle(request)` | `MetricBundle` | Metrics, trend, execution summary, attribution and budget |
| `getDataEnvelope(request)` | `ProviderEnvelope` | Combines both datasets with source and quality metadata |

`request` is limited to one `rtaId` and one explicit time range. Cross-RTA and account-wide requests are rejected before an Adapter is called.

## 3. ProviderEnvelope

```js
{
  contractVersion: '0.8',
  request: {
    rtaId: 'juliang-rta-2086',
    timeRange: { start: '...', end: '...' }
  },
  configSnapshot: {},
  metricBundle: {},
  meta: {
    providerId: 'mock-v08',
    platform: 'mock',
    sourceRecordId: 'mock:juliang-rta-2086',
    schemaVersion: '0.8',
    fetchedAt: '...',
    dataUpdatedAt: '...',
    freshnessSeconds: 0,
    qualityStatus: 'ok',
    missingFields: []
  }
}
```

The Provider does not generate diagnosis results. The rule engine remains the authority for D1-D14, scenario recognition and cause selection. `QueryContext` and `EV-*` evidence are built after normalized data enters the diagnosis pipeline.

## 4. Adapter Boundary

Authentication, pagination, rate limiting, retries, timeouts, upstream error codes and media-specific field mapping belong to an Adapter. They must not enter the rule engine.

Adapters return normalized contract objects or a `ProviderError` with one of these codes:

- `INVALID_REQUEST`
- `AUTH_REQUIRED`
- `PERMISSION_DENIED`
- `NOT_FOUND`
- `RATE_LIMITED`
- `TIMEOUT`
- `UPSTREAM_UNAVAILABLE`
- `SCHEMA_MISMATCH`
- `DATA_INSUFFICIENT`
- `DATA_STALE`
- `NOT_IMPLEMENTED`
- `INTERNAL`

Retryability is explicit on every error. Authentication, permission and schema errors are not retried automatically.

## 5. Read-only Invariants

- Provider capabilities must declare `readOnly: true`.
- Only `current_rta_only` scope is accepted.
- No method may mutate budget, bid, strategy, experiment or media configuration.
- Credentials stay on the server side and never enter GitHub Pages or browser state.
- Provider metadata is retained through `QueryContext` and evidence output.
- Missing, stale or conflicting data degrades to structured refusal instead of guessed values.

## 6. Migration Batches

1. Contract: add the shared contract, validation and Provider-specific tests.
2. Mock extraction: move existing Mock data access behind `MockMediaDataProvider` without changing visible behavior. This batch is complete for the Demo record/list access paths.
3. Replay Adapter: normalize synthetic media responses and add freshness/cache/error degradation. This batch uses `ReplayMediaAdapter` and does not make network calls. It is intentionally separate from the public Demo until the read-only tool layer consumes Provider envelopes end to end.
4. Tool integration: route read-only assistant tools through the Provider and preserve `EV-*` evidence validation.

Each batch must keep all five V0.7 validation groups passing.
