# V0.9 Staging 只读 Adapter 设计

## 1. 范围与不变量

本文仅定义服务端 Staging Adapter 的实现边界，不实现网络模块。真实联调必须等待 API 文档、字段核验、脱敏样本、测试凭证/权限和明确的 Staging 授权。

- 复用 V0.8 `MediaDataProvider`：`getConfigSnapshot(request)`、`getMetricBundle(request)`、`getDataEnvelope(request)`。
- `contractVersion` / `meta.schemaVersion` 保持 `0.8`，请求只允许单个 `rtaId`、显式 `timeRange` 和 `current_rta_only`。
- Provider `capabilities.readOnly` 必须为 `true`；禁止预算、出价、策略、实验或媒体配置写操作。
- Adapter 负责鉴权、HTTP、分页、限流、超时、重试、错误映射和媒体字段规范化；规则引擎只消费 `ConfigSnapshot` / `MetricBundle`，不得感知媒体 HTTP 语义。
- 字段输出以《V0.9 字段映射基线》为唯一映射口径；缺失、陈旧、冲突数据不得猜测。

## 2. 组件边界

```text
服务端调用方
  -> request 校验（单 RTA、显式时间范围）
  -> StagingMediaAdapter
       -> env 凭证读取 / Authorization 注入
       -> 本地并发与速率门控
       -> HTTP + AbortController 超时
       -> 有界分页
       -> 白名单重试
       -> 上游错误映射
       -> 字段规范化与 schema 校验
  -> ProviderEnvelope
  -> 规则引擎 / QueryContext / EV-*（媒体无感知）
```

凭证、原始上游响应和媒体专有字段不得穿透到规则引擎或浏览器。Adapter 可以在服务端短暂处理原始响应，但只返回规范化对象或 `ProviderError`。

## 3. 三方法语义

| 方法 | 服务端语义 | 输出 |
| --- | --- | --- |
| `getConfigSnapshot(request)` | 查询当前 RTA 的配置、账户绑定、策略、实验、组与变更；完成有界分页后一次性规范化 | `{ data: ConfigSnapshot, meta: ProviderMeta }` |
| `getMetricBundle(request)` | 按 `timeRange` 查询指标、趋势、执行摘要、回传和预算扩展数据 | `{ data: MetricBundle, meta: ProviderMeta }` |
| `getDataEnvelope(request)` | 合并前两者；可并行但共享调用预算与限流器；合并 missing fields 并做最终校验 | `ProviderEnvelope` |

如果上游无法提供某子域，应以 `meta.missingFields` 的完整规范化路径记录，并按质量规则标记；关键域不足时抛 `DATA_INSUFFICIENT`，不得用零值代替未知值。

## 4. HTTP 语义

### 4.1 鉴权注入

- 凭证只从进程环境变量读取，命名见安全审计设计；不得来自请求体、URL、前端、配置文件或仓库。
- HTTP 客户端在最后发送点注入 `Authorization: Bearer <token>`；业务层和日志层不得接触完整 Header。
- 缺少/空凭证在发请求前抛 `AUTH_REQUIRED`；上游确认 Token 无效或过期也映射为 `AUTH_REQUIRED`。
- Adapter 不接受调用方覆盖 `Authorization`，不把 Token、Secret、Cookie 或签名串写入 error details。

### 4.2 分页

- 分页器由接口配置声明 `cursor`、`page` 或 `offset`，不得自动猜测。
- 每次查询须设 `maxPages`、`maxRecords` 和整次 deadline；任一上限触发且结果不完整时标记 `partial`，关键数据不完整则抛 `DATA_INSUFFICIENT`。
- cursor 必须原样作为不透明值处理；检测 cursor 重复，避免死循环。
- 跨页记录按上游稳定主键去重；无稳定主键时不得静默去重，记为数据质量问题。
- 任一页失败遵循同一错误映射与重试策略；不得返回“看似完整”的前若干页。

### 4.3 限流

- 两层门控：进程内最大并发数与令牌桶速率；均以环境配置设置保守值，并受外部 API 文档最终约束。
- 所有三个 Provider 方法共享同一 `providerId + credential identity` 限流器，避免分别放大流量。
- 收到 429 或明确限流业务码时映射 `RATE_LIMITED`；优先遵守合法 `Retry-After`，否则使用带抖动的指数退避。
- 限流等待计入整次调用 deadline；不得通过无限排队规避超时。

### 4.4 超时

- 每个 HTTP attempt 使用 `AbortController`；调用 deadline 到达时中止请求和后续分页。
- 区分 attempt timeout 与 overall timeout，但对外都映射 `TIMEOUT`，差异仅放在不含敏感信息的 `details.phase`。
- 连接超时、单页超时、整次调用超时的数值必须配置且有硬上限；外部文档未补齐前不得写死为媒体 SLA。

### 4.5 重试

自动重试白名单严格限定为：`RATE_LIMITED`、`TIMEOUT`、`UPSTREAM_UNAVAILABLE`。每次重试均受最大次数与整次 deadline 约束，采用指数退避加随机抖动，并记录 attempt 数。

以下错误不自动重试：`INVALID_REQUEST`、`AUTH_REQUIRED`、`PERMISSION_DENIED`、`NOT_FOUND`、`SCHEMA_MISMATCH`、`DATA_INSUFFICIENT`、`DATA_STALE`、`NOT_IMPLEMENTED`、`INTERNAL`。特别地，鉴权、权限和 schema 错误禁止重试。Retryability 必须与错误码白名单一致，不能由上游任意字段提升。

## 5. ProviderError 锁定

仅允许以下 12 类，不新增错误码：

`INVALID_REQUEST`、`AUTH_REQUIRED`、`PERMISSION_DENIED`、`NOT_FOUND`、`RATE_LIMITED`、`TIMEOUT`、`UPSTREAM_UNAVAILABLE`、`SCHEMA_MISMATCH`、`DATA_INSUFFICIENT`、`DATA_STALE`、`NOT_IMPLEMENTED`、`INTERNAL`。

### 5.1 上游错误映射

HTTP 状态仅为典型对照；优先结合已核验的上游业务码和响应结构，且不得把未经解析的上游错误体直接暴露。

| 上游情形 | 典型 HTTP | ProviderError | retryable | 映射说明 |
| --- | --- | --- | --- | --- |
| 本地请求缺 `rtaId`、时间范围非法、跨 RTA/账户范围 | 未发请求 / 400 | `INVALID_REQUEST` | 否 | Provider 边界先拒绝 |
| 服务端未配置凭证；Token 无效或过期 | 未发请求 / 401 | `AUTH_REQUIRED` | 否 | 触发凭证检查/轮换流程，不自动重试 |
| Token 有效但无接口、账户或 RTA 权限 | 403 | `PERMISSION_DENIED` | 否 | 不把资源存在性泄露给未授权调用方 |
| 已授权范围内资源不存在 | 404 | `NOT_FOUND` | 否 | 仅在确认权限后使用 |
| 上游配额/并发限制 | 429 | `RATE_LIMITED` | 是 | 遵守 `Retry-After` 与调用 deadline |
| HTTP attempt 或 overall deadline 超时/主动 abort | 408、504 或客户端 abort | `TIMEOUT` | 是 | 用户取消若未来引入，应单独在调用层处理，不伪装超时 |
| 上游临时故障、网关错误、连接重置/DNS 临时失败 | 502、503 | `UPSTREAM_UNAVAILABLE` | 是 | 仅临时性故障；确定性 5xx 仍须按业务码核验 |
| 响应 JSON 不能解析、类型/枚举/schema 不符、RTAID 不一致 | 200、422、5xx 均可能 | `SCHEMA_MISMATCH` | 否 | 保存脱敏诊断摘要，禁止自动重试 |
| 必需域缺失、分页被上限截断、样本量不足，无法可靠诊断 | 200、206 | `DATA_INSUFFICIENT` | 否 | 未知不可填零；可选字段缺失可降级为 `partial` |
| `dataUpdatedAt` 超 freshness SLA | 200 | `DATA_STALE` | 否 | `fetchedAt` 不得替代更新时间 |
| 接口/媒体能力在当前 Adapter 明确未实现 | 501 或本地 | `NOT_IMPLEMENTED` | 否 | 仅能力缺失；不得用于一般上游故障 |
| Adapter 自身未分类异常/不变量破坏 | 500 或本地 | `INTERNAL` | 否 | 先包装、脱敏并审计；不得吞掉为正常空结果 |

业务校验错误若明确表示调用参数不合法，映射 `INVALID_REQUEST`；若表示上游响应违反约定，映射 `SCHEMA_MISMATCH`。两者不得仅凭 HTTP 400/422 猜测。

### 5.2 错误对象约束

`ProviderError` 延续 V0.8 字段：`code`、`message`、`retryable`、`providerId`、`details`。`details` 只允许保存白名单诊断字段，例如 `phase`、`attempt`、`httpStatus`、脱敏 `upstreamCode`、`missingFields`、`freshnessSeconds`；禁止 Header、Token、Cookie、完整 URL、原始响应体和个人标识。

## 6. 质量降级

| 情形 | `meta.qualityStatus` / 结果 | 处理 |
| --- | --- | --- |
| 完整且满足 freshness | `ok` | 正常进入规则引擎 |
| 非关键字段缺失、可解释地继续 | `partial` + `missingFields[]` | 只运行证据充分的规则；查询层结构化说明缺口 |
| 数据超过 freshness SLA 但策略允许标记 | `stale` | 结构化拒绝时效性结论；策略要求严格时抛 `DATA_STALE` |
| 关键域/样本量不足 | 无 Envelope；`DATA_INSUFFICIENT` | 不猜测，不生成权威指标 |
| 网络/权限/schema 等失败 | 无 Envelope；对应 `ProviderError` | 审计失败并结构化降级 |

`qualityStatus` 输出值锁定为 `ok`、`partial`、`stale`；`insufficient` 和 `failure` 是审计/监控 outcome，不伪装成成功 Envelope 的质量值。

## 7. 双轨关系

- 服务端 Staging Adapter 与 `demo/v6` 的离线 `MockMediaDataProvider`、`ReplayMediaAdapter` 并存，Provider 接口相同、部署入口隔离，互不导入、互不覆盖。
- GitHub Pages / 浏览器继续只使用离线 Mock/Replay；Staging 凭证与网络能力只存在服务端。
- `demo/v6/` 的 UMD 双端实现保持不变；V0.9 不修改 Demo 行为、Golden Case 或既有验收。
- 规则引擎、场景识别、QueryContext 和 `EV-*` 证据只读取规范化契约，保持媒体无感知；不得出现 HTTP 状态、媒体字段名或 Token 逻辑。

## 8. 回放样本格式规范

### 8.1 存放与命名

P2 样本统一放入 `server/test/fixtures/replay-samples/`；本阶段只定义格式，不创建目录或样本文件。

文件名：`<platform>__<scenario>__<case-id>.json`。

- `<platform>`：小写字母、数字和连字符，如 `juliang`、`tencent`、`generic`。
- `<scenario>`：严格为 `normal`、`empty`、`latency`、`permission-denied`、`rate-limited`、`timeout`、`missing-fields`、`error-response` 之一。
- `<case-id>`：小写字母、数字和连字符，不含真实账户/RTA/用户标识。
- 样本必须为合成或已脱敏数据，不得包含凭证、真实公司数据、完整请求 Header 或 Cookie。

### 8.2 通用 JSON Schema

以下为 P2 样本的 Draft 2020-12 结构约束。`request` 是 Provider 请求；`upstream` 表达可回放的 HTTP 行为；`expected` 锁定预期规范化结果或既有 ProviderError。

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://example.invalid/rta/v0.9/replay-sample.schema.json",
  "type": "object",
  "additionalProperties": false,
  "required": ["sampleVersion", "scenario", "request", "upstream", "expected"],
  "properties": {
    "sampleVersion": { "const": "0.9" },
    "scenario": {
      "enum": ["normal", "empty", "latency", "permission-denied", "rate-limited", "timeout", "missing-fields", "error-response"]
    },
    "request": {
      "type": "object",
      "additionalProperties": false,
      "required": ["rtaId", "timeRange", "dataScope"],
      "properties": {
        "rtaId": { "type": "string", "minLength": 1 },
        "timeRange": {
          "type": "object",
          "additionalProperties": false,
          "required": ["start", "end"],
          "properties": {
            "start": { "type": "string", "format": "date-time" },
            "end": { "type": "string", "format": "date-time" }
          }
        },
        "dataScope": { "const": "current_rta_only" },
        "requestId": { "type": ["string", "null"] }
      }
    },
    "upstream": {
      "type": "object",
      "additionalProperties": false,
      "required": ["pages"],
      "properties": {
        "pages": {
          "type": "array",
          "minItems": 1,
          "items": {
            "type": "object",
            "additionalProperties": false,
            "required": ["status", "delayMs", "body"],
            "properties": {
              "status": { "type": "integer", "minimum": 100, "maximum": 599 },
              "delayMs": { "type": "integer", "minimum": 0 },
              "headers": {
                "type": "object",
                "additionalProperties": { "type": "string" },
                "propertyNames": { "not": { "pattern": "^[Aa][Uu][Tt][Hh][Oo][Rr][Ii][Zz][Aa][Tt][Ii][Oo][Nn]$|^[Cc][Oo][Oo][Kk][Ii][Ee]$|^[Ss][Ee][Tt]-[Cc][Oo][Oo][Kk][Ii][Ee]$" } }
              },
              "body": {},
              "cursor": { "type": ["string", "null"] }
            }
          }
        }
      }
    },
    "expected": {
      "oneOf": [
        {
          "type": "object",
          "additionalProperties": false,
          "required": ["kind", "envelope"],
          "properties": {
            "kind": { "const": "success" },
            "envelope": {
              "type": "object",
              "required": ["contractVersion", "request", "configSnapshot", "metricBundle", "meta"],
              "properties": { "contractVersion": { "const": "0.8" } }
            }
          }
        },
        {
          "type": "object",
          "additionalProperties": false,
          "required": ["kind", "error"],
          "properties": {
            "kind": { "const": "error" },
            "error": {
              "type": "object",
              "additionalProperties": false,
              "required": ["code", "retryable"],
              "properties": {
                "code": {
                  "enum": ["INVALID_REQUEST", "AUTH_REQUIRED", "PERMISSION_DENIED", "NOT_FOUND", "RATE_LIMITED", "TIMEOUT", "UPSTREAM_UNAVAILABLE", "SCHEMA_MISMATCH", "DATA_INSUFFICIENT", "DATA_STALE", "NOT_IMPLEMENTED", "INTERNAL"]
                },
                "retryable": { "type": "boolean" }
              }
            }
          }
        }
      ]
    }
  }
}
```

样本中的成功 `envelope.meta` 必须含 V0.8 必填元数据；动态字段（如 `fetchedAt`、attempt 次数）由测试 harness 使用明确占位/匹配器处理，不得删掉必填字段。

### 8.3 八类场景约束

| scenario | `upstream` 约束 | `expected` 断言 |
| --- | --- | --- |
| `normal` | 2xx，完整且可分页的合成数据，`delayMs` 小于 timeout | `success`；Envelope 通过 V0.8 校验，`qualityStatus=ok` |
| `empty` | 2xx，合法空集合/零请求窗口 | 若业务上合法则 `success` 且计数为 0、比例未知不得伪造；若关键配置为空则 `DATA_INSUFFICIENT`，由样本明确选择 |
| `latency` | 2xx，非零延迟但未越过 timeout | `success`；审计耗时可观测，不因“慢但未超时”误报 `TIMEOUT` |
| `permission-denied` | 403 或已核验的无权限业务码 | `PERMISSION_DENIED`、`retryable=false` |
| `rate-limited` | 429，可含安全的 `Retry-After` | 最终成功时验证重试次数；重试耗尽时 `RATE_LIMITED`、`retryable=true` |
| `timeout` | `delayMs` 超过 attempt/overall timeout | `TIMEOUT`、`retryable=true`；验证 AbortController 中止和有界重试 |
| `missing-fields` | 2xx，删去指定规范化字段 | 非关键缺失为 `partial + missingFields`；关键缺失为 `DATA_INSUFFICIENT` 或结构错误为 `SCHEMA_MISMATCH`，样本须明确 |
| `error-response` | 非 2xx、非法 JSON 或带业务错误码 | 按映射表得到既有 ProviderError；不得把原始错误体/敏感字段泄露到输出 |

同一 scenario 可有多个 case，但每个文件只描述一个确定行为；不得用运行时随机数改变预期结果。
