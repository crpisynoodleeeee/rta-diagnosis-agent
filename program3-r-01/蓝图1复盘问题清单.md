## 二、问题明细

### Q1 · 标题名不副实（P0）

**现状**：标题为「蓝图1：智能投放数据交互（执行边界分级整合版）」。

**问题**：实际内容已不止"执行边界分级"，还包含「载体设计」「场景二三方数据流改造」。标题只点出一个横切面，名不副实。

**建议**：改为更概括的标题，如「智能投放数据交互（执行边界 + 载体设计整合版）」或去掉括注，仅保留「智能投放数据交互蓝图」。

---

### Q2 · 两个横切面各自为政，缺汇总矩阵（P0）

**现状**：「执行边界分级」（L0-L3）和「载体设计」（IM/Web/SDK/守护进程）是两个独立的横切面，各有各的表，没有关联。

**问题**：两个维度在场景里其实是**耦合**的，读者需要自己在脑子里拼接：
- 场景四：`L3 紧急止损`（执行边界）↔ `API/守护进程`（载体）——秒级止损必须配秒级执行载体
- 场景三：`L2 自动暂停`（执行边界）↔ `IM 推送`（载体）——自动执行和推送有时序关系

**建议**：新增一张「场景 × 执行边界 × 载体」汇总矩阵，一表看全三个维度的对应关系。示例结构：

| 场景 | 核心动作 | 执行分级 | 载体 | 关键约束 |
|---|---|---|---|---|
| 一 竞价感知 | 出价调整 | L1/L2 | 边缘/守护进程 | 毫秒级，算力靠近网关 |
| 二 效果预测 | 采纳方案 | L1 | Web 面板 | 看报告+置信区间 |
| 三 智能预警 | 暂停/调价 | L2/L3/L1 | IM 推送 + Web 面板 | 告警秒达，处理回 Web |
| 四 应急暂停 | 暂停/阻断 | L3 | IM 通知 + API/守护进程 | 秒级执行，不等人在 IM 点 |
| 五 趋势分析 | 出报告 | L0 | Web 面板 | 看图表趋势 |
| 六 优化建议 | 采纳建议 | L1/L2 | Web 面板（IM 通知） | 建议配数据，采纳在 Web |
| 七 NL 查询 | 查询 | L0 | IM | 对话式问数 |

### Q3 · 场景三时序矛盾未修复（P1）

**现状**：场景三 flowchart 中：
```
⑥ 命中判定
  ├── ⑦b 自动执行调价/暂停   ← 已自动执行
  └── ⑧ 运营确认/调整/忽略/退回  ← 然后才让运营确认
```

**问题**：到底是「先自动执行、再让人确认」（先斩后奏），还是「先让人确认、再执行」（先奏后斩）？原图两个都画了，顺序矛盾。

**影响**：这是逻辑硬伤，若蓝图1 对外展示会被直接挑战。

**建议**：按执行边界分叉重画时序——命中判定后分叉：
- 减支/止损类（暂停）→ 自动执行 L2/L3
- 增支类（提价）→ 生成建议 → 人工确认 L1 → 执行

注意：此问题在「执行边界」章节已有文字修正（⑦b 拆成两条），但 **flowchart 图本身未同步修改**，需把图的时序也改对。

---

### Q4 · 结尾"统一数据管道"未纳入新增内容（P1）

**现状**：结尾的「所有场景统一数据管道」仍是原蓝图老版本：
```
媒体回调 → 报表中心(Doris) ← 归因数据补充
                  ↓
          ← 智能问数模块 →
                  ↓
   Agent分析 → 创建监测中心任务 → 执行落地
```

**问题**：未体现「执行边界」和「载体」两个新维度，与前面新增内容脱节。

**建议**：更新数据管道，纳入新维度，例如在"Agent分析 → 执行落地"之间补上执行分级 gate（L1 人工确认 / L2 护栏 / L3 自动），或在管道旁标注每个环节的载体。

---

### Q5 · 场景三定位模糊（P2）

**现状**：场景三「智能分析及预警」名义上是 AI Agent，但拆解后：
- ② 翻译监测参数 = NL 解析（✅ AI）
- ④⑤ 定时查指标 = 定时任务 + SQL（❌ 工程）
- ⑥ 命中判定 = if 阈值（❌ 规则）
- ⑦ 告警/执行 = 触发动作（❌ 工程）

**问题**：场景三的"智能"只在第②步，本质是「规则引擎」而非「AI 分析」。命中之后缺一个"分析为什么命中、影响多大"的环节。

**建议**：明确场景三定位——要么承认它是规则引擎（改名"智能规则监测"），要么在命中之后补"AI 归因分析"环节（为什么命中 + 影响评估），把"告警"升级为"告警 + 诊断"。

---

### Q6 · 缺"诊断归因层"（P2）

**现状**：原蓝图 7 个场景中：
- 场景一/三 告诉你"指标超阈值了"（知道出事）
- 场景五 告诉你"趋势在下降"（知道异常）
- 场景六 告诉你"该调什么"（给建议）

**问题**：没有一个场景回答"为什么"——"感知（出事）→ 建议（怎么办）"之间，缺"诊断（为什么）"这一环。这是结构性空白。

**影响**：按蓝图跑，"CPA 超标 → 直接暂停"，运营不知道原因。

**建议**：新增第 8 个场景「诊断归因 Agent」，放在感知之后、建议之前，专门做"多源信号合成因果链 + 证据"。

---

### Q7 · 缺"三方数据底座"前置章节（P2）

**现状**：场景二已改造为"三方平权汇合 → 特征数据集"，但三方数据（投放 / 转化 / 行业）的概念只在场景二内部，未提升为全局前置章节。

**问题**：三方数据底座其实是整个 AI 投放的数据地基——场景一（投放+行业）、三（投放）、五（投放+行业）、六（三方）各自只是从这个底座取自己需要的部分。缺前置章节导致各场景数据来源重复且不统一。

**建议**：新增「三方数据底座」前置章节，定义三方数据的来源、口径、对齐规则，各场景数据来源统一引用它。
