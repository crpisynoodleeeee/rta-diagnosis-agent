执行分级定义
|级别|定义|典型动作|触发方式|
|-|-|-|-|
|L0 只读/只告警|零资金风险，只通知不落地|企微告警、报表推送、趋势报告|自动|
|L1 人工确认后执行|有资金风险，人点确认才落地|提价、加预算、素材替换、放量、采纳预测方案|人工 gate|
|L2 有护栏的自动|低风险可逆，带护栏自动执行，事后可查可撤销|降价、减预算、调价监测任务创建|自动 + 护栏|
|L3 紧急止损全自动|不执行损失更大，秒级自动 + 强留痕|合规暂停、风控阻断|自动（唯一例外）|

载体三要素（一个载体 = 算力位置 × 入口 × 形态）
|要素|问题|选项|
|-|-|-|
|算力位置|Agent 逻辑跑在哪|后端服务 / 边缘节点 / 端上|
|入口|用户从哪接触它|IM 对话 / Web 面板 / API 调用 / 无 UI|
|形态|它长什么样|对话框 / 内嵌抽屉 / SDK / 无感守护|
载体分类说明
|载体|形态|人类介入|时效|典型场景|
|-|-|-|-|-|
|IM 平台（企微/飞书/钉钉）|对话机器人 + 推送|高|秒级|告警通知、NL 问数、轻确认|
|Web 内嵌面板|页面抽屉/侧边栏|中|即时|看报告、看趋势、审阅式决策|
|SDK/API|程序化调用，无 UI|低|程序决定|嵌入第三方系统、能力产品化|
|定时任务/守护进程|无 UI 后台|极低|定时/事件驱动|监测、自动止损|
|边缘/端上 Agent|部署在网关旁|无|毫秒级|实时竞价（RTA）|
逐场景载体分派
|场景|载体|决策依据|
|-|-|-|
|一 竞价感知|边缘/守护进程|毫秒级，不能等人回话；算力须靠近投放网关|
|二 效果预测|Web 面板|看报告+置信区间，需可视化|
|三 智能预警|IM 推送 + Web 面板|告警秒达 IM，处理回 Web 看数据|
|四 应急暂停|IM 强提醒（通知）+ API/守护进程（执行）|秒级通知走 IM，秒级执行走 API，不等人在 IM 里点|
|五 趋势分析|Web 面板|看图表趋势|
|六 优化建议|Web 面板（IM 通知）|建议配数据看，采纳在 Web 点|
|七 NL 查询|IM 最自然|"华为上周 CPA 多少"天然是对话|
IM 载体的边界（三条红线）
|红线|说明|
|-|-|
|看不了复杂数据|IM 卡片能显示几个数字，展示不了趋势图、原因树、置信区间|
|做不了审阅式决策|IM 里点"采纳"容易，看完整证据再采纳难，易变"盲目点确认"|
|消息流会淹没|告警多了变噪音，运营一静音 Agent 就失效|
SDK 的定位（与 IM 是两条并行线）
|路线|含义|示例|
|-|-|-|
|IM = 给人用的入口|对话、通知、问数|运营在企微问"华为 CPA 多少"|
|SDK = 给程序用的接口|把 Agent 能力嵌入第三方系统/工具|把"预测"能力 SDK 化嵌入客户投放系统|
