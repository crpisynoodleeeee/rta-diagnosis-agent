## 3. 媒体 RTAID 映射总览
### 3.1 功能定位
XAD 前端统一使用 **RTAID** 命名，列表、筛选、新建、实验配置、策略筛选中均展示为 RTAID。不同媒体的实际字段由系统按媒体规则映射。

本期 **VIVO** 平台默认预设 1 个 RTAID到用户RTAID中，前端需对用户可见，限制=仅可查看，其余操作禁用



<img src="https://cdn.nlark.com/yuque/0/2026/png/57981667/1783675245310-cc792dc5-3764-4a29-8628-c56ed21451a0.png" width="1195" title="" crop="0,0,1,1" id="udf6ca3f6" class="ne-image">  
OPPO、荣耀请求中均存在可映射为 RTAID 的字段，不需要平台默认预设 RTAID。

### 3.2 媒体映射关系
| 媒体 | XAD 字段 | 媒体实际字段 | 请求中是否可识别 RTAID | 返回中是否可识别 RTAID | 产品处理 |  |
| --- | --- | --- | --- | --- | --- | --- |
| 小米 | RTAID | token | 是，`adReqs.token` | 是，`adResps.token` | 用户在 XAD 维护 RTAID，实际映射为 token；token 与创意绑定 | <img src="https://cdn.nlark.com/yuque/0/2026/png/57981667/1783654765318-a6da5b8d-626a-46de-921d-ed929331eef3.png" width="2552" title="" crop="0,0,1,1" id="uc2f89a12" class="ne-image"><img src="https://cdn.nlark.com/yuque/0/2026/png/57981667/1783654785849-83d8c928-94dc-4b6c-a602-e675b494b480.png" width="2552" title="" crop="0,0,1,1" id="uf644d3ff" class="ne-image"><br/><img src="https://cdn.nlark.com/yuque/0/2026/png/57981667/1783654795700-cb31d16f-13cc-47d1-a90d-9cf680a6f1f0.png" width="2552" title="" crop="0,0,1,1" id="u826e78af" class="ne-image"><img src="https://cdn.nlark.com/yuque/0/2026/png/57981667/1783654803283-822e54eb-1ae8-4a6b-8f3e-30793b98b2e0.png" width="2552" title="" crop="0,0,1,1" id="u4f62ac7c" class="ne-image"><img src="https://cdn.nlark.com/yuque/0/2026/png/57981667/1783654811053-4f1f6101-88c0-4187-8d22-6d2ec6f36533.png" width="2552" title="" crop="0,0,1,1" id="ue49c7cf0" class="ne-image"> |
| VIVO | RTAID | type / advertiser_account | 否，请求不包含账户 / RTAID | 是，返回 `type`<br/> 或 `advertiser_account` | 平台默认预设 1 个 RTAID；请求阶段不判断 RTAID，返回阶段通过 type 或账户承接 | |
| OPPO | RTAID | ad_type_list / agree_type | 是，`ad_type_list` | 是，`agree_type_list`<br/> / `factors.agree_type` | 用户在 XAD 维护 RTAID，实际映射为 ad_type_list 中的账户策略类型；返回用 agree_type 判断命中 | |
| 荣耀 | RTAID | rtaId | 是，`rtaIdList` | 是，`rtaInfoList.rtaId` | 用户在 XAD 维护 RTAID，实际映射为 rtaId，与 XAD RTAID 语义一致 | |


；VIVO 请求不包含广告引擎召回的账户 / RTAID 信息；OPPO 请求字段包含 `ad_type_list`；荣耀请求字段包含 `rtaIdList`。

### 3.3 RTAID 配置边界
| 媒体 | 是否需要平台预设 RTAID | 是否支持用户在 XAD 维护 RTAID | 说明 |
| --- | --- | --- | --- |
| 小米 | 否 | 是 | 用户维护的 RTAID 映射为小米 token，创意层选择 |
| VIVO | 是，默认 1 个 | 否 | VIVO 请求不带 RTAID，仅保留 1 个平台默认 RTAID 用于归属和返回承接 |
| OPPO | 否 | 是 | 用户维护的 RTAID 映射为 OPPO 账户策略类型 / ad_type_list |
| 荣耀 | 否 | 是 | 用户维护的 RTAID 映射为荣耀 rtaId，账户能力按媒体能力决定，暂不明确 |


说明：

1.  XAD 中维护 RTAID，不代表向媒体侧创建 RTAID。 
2.  小米、OPPO、荣耀的 RTAID 来自媒体侧已有字段映射。 
3.  VIVO 不支持用户新增多个 RTAID，仅使用平台默认 RTAID。 
4.  VIVO 返回 `type` 时，需与平台默认 RTAID 的承接配置保持一致。 
5.  VIVO 返回 `advertiser_account` 时，按账户列表判断参竞结果。 

### 3.4 分媒体处理规则
#### 3.4.1 小米
| 项目 | 规则 |
| --- | --- |
| RTAID 来源 | 用户在 XAD 维护 |
| 媒体映射字段 | token |
| 请求映射 | `adReqs.token` |
| 返回映射 | `adResps.token` |
| 绑定对象 | token |
| 页面联动 | 选择小米后展示「token」字段，支持一个RTAID填写一个token字段 |
| 处理规则 | 用户需要自行完成 token 需与小米创意绑定，未绑定 token 的创意不触发 RTA 请求 |


#### 3.4.2 VIVO
| 项目 | 规则 |
| --- | --- |
| RTAID 来源 | 平台默认预设 1 个 |
| 是否允许新增 | 不允许 |
| 是否允许删除 | 不允许 |
| 请求映射 | 无，请求不包含账户 / RTAID |
| 返回映射 | `type`<br/> 或 `advertiser_account` |
| 处理规则 | 请求阶段不判断 RTAID；返回阶段通过 type 或账户承接参竞结果 |
| 限制规则 | `type`<br/> 和 `advertiser_account`<br/> 不支持同时返回 |


#### 3.4.3 OPPO
| 项目 | 规则 |
| --- | --- |
| RTAID 来源 | 用户在 XAD 维护 |
| 媒体映射字段 | ad_type_list / agree_type |
| 请求映射 | `ad_type_list` |
| 返回映射 | `agree_type_list`<br/> / `factors.agree_type` |
| 处理规则 | 将 ad_type_list 中的账户策略类型映射为 XAD RTAID |
| 参竞判断 | 以返回的 agree_type 判断命中的账户策略类型 |


#### 3.4.4 荣耀
| 项目 | 规则 |
| --- | --- |
| RTAID 来源 | 用户在 XAD 维护 |
| 媒体映射字段 | rtaId |
| 请求映射 | `rtaIdList` |
| 返回映射 | `rtaInfoList.rtaId` |
| 账户绑定 | 支持 |
| 处理规则 | RTAID 可直接用于策略筛选、实验归属、出价归属和分桶归属 |

## 6. RTA 实验列表
### 6.1 入口 / 路径：RTA → RTA 实验
RTA 实验用于配置普通实验和 AB 实验，支持将已发布策略绑定到指定 RTAID 下，并通过实验规则控制不同策略组合的生效流量。

### 6.2 筛选项
筛选项保持现有逻辑不变。

| 筛选项 | 说明 |
| --- | --- |
| 实验名称 / ID | 支持模糊搜索 |
| 实验类型 | 普通实验、AB 实验 |
| 媒体 | 巨量、腾讯、华为信息流，小米应用市场、VIVO应用市场、OPPO应用市场、荣耀应用市场 |
| RTAID | 根据媒体联动 |
| 实验状态 | 草稿、实验中、已暂停、已结束 |
| 创建人 | 按创建人筛选 |
| 时间范围 | 按创建时间 / 更新时间筛选 |


### 6.3 列表覆盖人数字段
| 字段 | 说明 |
| --- | --- |
| 覆盖人数 | 展示当前 RTA 实验下关联全部 RTA 策略加总后的覆盖人数 |


统计规则：

| 场景 | 展示规则 |
| --- | --- |
| 正常计算 | 取当前实验下所有配置的 RTA 策略的人群覆盖人数之和，按用户字段去重统计 |
| 覆盖人数未计算 | 展示「未计算」 |
| 覆盖人数计算失败 | 展示「计算失败」 |

## 7. RTA 实验状态与操作
| 实验状态 | 支持操作 | 限制规则 |
| --- | --- | --- |
| 草稿 | 查看、编辑、删除、发布、复制 | 无 |
| 实验中 | 暂停、结束、复制、查看数据报表 | 不可直接修改分桶配置、策略组合、发布时间 |
| 已暂停 | 编辑、恢复、结束、复制、查看数据报表 | 编辑后需重新满足发布校验 |
| 已结束 | 查看、复制、编辑基础信息、查看数据报表、重新启用 | 不可修改策略配置、分桶配置、历史生效配置 |


操作入口保持现有逻辑：

```plain
查看
编辑基础信息
暂停
恢复
结束
删除
复制
查看数据报表
```

## 9. AB 实验分桶配置
RTAID提示需修改提示语

### 9.1 展示条件
当实验类型选择 **AB 实验** 时，页面展示分桶配置能力。

AB 实验用于在同一 RTAID 下配置对照组和多个实验组，通过分桶方式控制不同策略组合的生效流量。

### 9.2 分桶方式字段
| 字段 | 类型 | 是否必填 | 说明 |  |

### 9.3 分桶方式定义
| 分桶方式 | 定义 |
| --- | --- |
| 平台分桶 | 系统基于媒体侧传入的桶 ID，与系统配置中维护的平台分桶 ID 进行匹配 |
| 客户分桶 | 由 XAD 平台根据实验中配置的分桶字段自主计算桶号，不依赖媒体官方分桶 ID |


### 9.4 分桶方式适用范围
| 媒体 | 平台分桶 | 客户分桶 | 规则 |
| --- | --- | --- | --- |
| 巨量 | 支持 | 支持 | 沿用现有逻辑 |
| 腾讯 | 支持 | 支持 | 沿用现有逻辑 |
| 华为 | 不支持 | 支持 | 华为不支持官方分桶，创建 AB 实验时应使用客户分桶 |
| 小米 | 不支持 | 支持 | 文档未看到媒体侧桶 ID / 实验 ID 字段，仅支持 XAD 内部分桶 |
| VIVO | 不支持 | 支持 | 可用 custom_exp_id 承接 XAD 实验 ID，但不等同于媒体平台分桶 |
| OPPO | 不支持 | 支持 | 可用 exp_id 承接 XAD 实验 ID，但不等同于媒体平台分桶 |
| 荣耀 | 不支持 | 支持 | 可用 rtaExpId 承接实验 ID，但桶号仍由 XAD 计算 |


边界说明：

1. **平台分桶** 的前提是媒体请求侧传入桶 ID，本次新增小米、VIVO、OPPO、荣耀文档未体现该类桶 ID 入参
2. VIVO / OPPO / 荣耀支持实验 ID 字段承接，不等于支持媒体官方平台分桶
3. 新增四家媒体创建 AB 实验时，分桶方式默认选择 **客户分桶**
4. 新增四家媒体不展示「平台分桶」选项；如保留选项，则置灰并提示不支持



## 10. 分桶分配
AB 实验后续配置页面继续复用当前已有的 **10 桶分配能力**

页面展示 10 个桶，每个桶默认代表 10% 流量。用户可将不同桶分配给对照组、实验组 A、实验组 B 等实验组，系统根据桶数自动计算各组流量占比

### 10.1 实验组配置规则
| 配置项 | 规则 |
| --- | --- |
| 默认实验组 | 默认生成 1 个对照组 + 1 个实验组 |
| 新增实验组 | 支持新增多个实验组 |
| 对照组 | 对照组不可删除 |
| 分桶数量 | 固定 10 个桶 |
| 单桶流量 | 每桶默认代表 10% 流量 |
| 分桶分配 | 每个组至少选择 1 个分桶 |
| 分桶唯一性 | 同一分桶不可重复分配给多个组 |
| 流量占比 | 根据各组分配桶数自动计算 |
| 总占比 | 各组分桶占比总和不得超过 100% |
| 发布后修改 | 发布后不可直接修改分桶，需按现有实验编辑规则处理 |


### 10.2 桶号来源
| 分桶方式 | 桶号来源 |
| --- | --- |
| 平台分桶 | 桶号来自媒体传入，并与系统配置的平台分桶 ID 匹配 |
| 客户分桶 | 桶号由 XAD 平台根据客户分桶字段配置计算生成 |


### 10.3 分桶兜底规则
| 分桶方式 | 异常场景 | 处理方式 |
| --- | --- | --- |
| 平台分桶 | 媒体未传桶 ID | 执行对照组策略 |
| 平台分桶 | 桶 ID 为空 | 执行对照组策略 |
| 平台分桶 | 桶 ID 不匹配 | 执行对照组策略 |
| 平台分桶 | 桶 ID 格式异常 | 执行对照组策略 |
| 客户分桶 | 匹配异常 | 执行对照组策略 |
| 客户分桶 | 分桶计算失败 | 执行对照组策略并记录异常 |

## 11. 配置实验-流程不变
配置实验用于维护实验下的策略组合。

普通实验和 AB 实验均复用策略组配置能力。普通实验直接配置策略组；AB 实验需在对照组和各实验组内分别配置策略组。

### 11.1 策略组配置区
| 字段 / 组件 | 说明 |
| --- | --- |
| 策略组容器 | 用于承载当前实验下全部策略组，默认生成 1 个策略组 |
| 新增策略组 | 点击后新增一个策略组，默认命名为“策略组 N” |
| 策略组名称 | 输入框，必填，默认按“策略组 1 / 策略组 2”生成，支持手动修改 |
| 删除策略组 | 删除当前策略组 |
| 组内逻辑关系 | 单选，支持 或（OR） |
| 添加 | 点击后，在当前策略组内新增一条策略配置行 |
| 删除策略 | 删除当前策略组内某条策略；若当前策略组仅剩 1 条策略，删除后保留空白态，不自动删除整个策略组 |


### 11.2 AB 实验策略组规则
| 场景 | 规则 |
| --- | --- |
| 对照组 | 至少配置 1 个策略组 |
| 实验组 | 每个实验组至少配置 1 个策略组 |
| 新增实验组 | 新增后需配置对应策略组 |
| 删除实验组 | 删除实验组时同步删除该组下策略组配置 |
| 分桶未配置 | 不允许发布实验 |
| 策略组未配置 | 任一实验组或对照组未配置策略组时，不允许发布实验 |


### 11.3 实验内规则关系
| 场景 | 规则 |
| --- | --- |
| 策略组之间 | 默认按“或（OR）”关系执行，不提供组间关系选择 |
| 策略组内部 | 支持配置为（OR）” |
| 组内关系为“或” | 组内每条策略可单独配置出价 |
| 组内关系为“且” | 组内全部策略共用同一个出价，出价规则在策略组层级统一设置 |
| 点击添加策略后 | 无需再次输入策略类型、实验策略、出价配置模式，仅需选择新增条件 |

## 17. 出价配置模式
**平台支持两种出价配置模式：**

**固定出价**

**模型出价**

### 17.1 固定出价
| 规则 | 说明 |
| --- | --- |
| 输入方式 | 用户手动输入出价系数、CPA / oCPX 出价或 CPC 出价 |
| 返回方式 | 系统按用户配置返回固定值 |
| 展示范围 | 根据媒体能力动态展示 |
| 小米 / OPPO | 仅允许配置出价系数 |
| VIVO / 荣耀 | 支持出价系数、CPC 出价、CPA / oCPX 出价 |
| 华为 | 支持出价系数、CPA 出价、CPC 出价 |


### 17.2 模型出价
| 规则 | 说明 |
| --- | --- |
| 输入方式 | 用户选择模型字段 |
| 字段来源 | 模型字段来自策略工厂的数据字段配置 |
| 数量限制 | 当前单个策略仅支持一个模型字段 |
| 输出要求 | 模型输出结果必须与当前选择的出价方式一致 |
| 小米 / OPPO | 模型输出只能映射为出价系数 |
| VIVO / 荣耀 | 模型输出可按所选出价方式映射为出价系数、CPC、CPA / oCPX |
| 华为 | 模型输出可按所选出价方式映射为出价系数、CPA、CPC |

## 18. 出价互斥与隐藏规则
| 场景 | 规则 |
| --- | --- |
| 同一策略配置项 | 出价系数、CPC 出价、CPA / oCPX 出价只能选择一种 |
| 小米 | 仅展示出价系数，不展示 CPC / CPA / oCPX |
| OPPO | 仅展示出价系数，不展示 CPC / CPA / oCPX |
| VIVO 同一 put_in_type | 不允许同时配置 rta_bid 和 boost_coef |
| VIVO put_in_type = 10000 | 本期不允许与具体 put_in_type 同时配置，避免优先级歧义 |
| 荣耀同一目标 | 不允许同时配置 priceRate 和 priceInfo / convPriceInfo |
| 华为同一策略 | 出价系数、CPA 出价、CPC 出价只能选择一种 |
| 模型出价 | 模型字段输出值必须与当前出价方式匹配，否则不允许保存 |
| 不支持的出价方式 | 不展示，不置灰 |
