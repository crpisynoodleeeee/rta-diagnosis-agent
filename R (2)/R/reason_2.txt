## 一、产品概述
### 1.1 背景与目标
当前 XAD 已具备事件中心、归因配置、回传策略、归因 / 再归因日志、回传执行日志等能力平台可基于事件中心中的业务事件、埋点事件、监测事件、投放链接事件和客户系统同步事件完成归因判断与媒体回传

随着投放链路扩展，现有配置中存在以下问题：

1. “媒体监控事件”“监测事件”“投放链接事件”等概念在不同页面中混用，用户难以判断当前字段选择的是业务事件，还是广告触点事件
2. 归因策略中的触发事件和条件匹配事件边界不够清晰
3. 回传策略中，单条回传条件无法明确当前条件对应哪个转化事件，也无法清晰展示该事件命中了归因策略中的哪个条件
4. 回传账号选择后，无法根据实际归因账户 ID 进一步过滤回传账号，存在跨账户回传风险
5. 分层回传命中哪条规则、按多少比例回传，当前日志中不够清晰，排查成本较高

### 1.2 本期目标
1. 统一将原“媒体监控事件”调整为“媒体触点事件”
2. 明确归因触发事件来自事件中心的业务事件和埋点事件
3. 明确归因条件中匹配的事件为媒体触点事件，可包含监测事件、投放链接事件、短链事件、中转页事件、媒体 callback 事件等
4. 回传策略中新增“转化事件”字段，用于选择当前关联归因策略下的目标转化事件和前序事件
5. 回传策略中“当用户发生”字段用于选择媒体触点事件
6. 用户选择“当用户发生”后，系统自动带出该媒体触点事件所属的归因策略条件
7. 归因策略条件展示需包含条件序号、媒体触点事件、归因口径和归因模型
8. 回传媒体事件必须依赖事件映射关系
9. 新增“根据归因账户 ID 过滤”开关，开启后根据归因记录中的归因账户 ID 匹配已选回传账号
10. 分层回传支持根据媒体触点事件字段、目标转化事件字段和归因结果字段做判断
11. 回传日志仅新增“回传规则”字段，用于记录分层回传命中的规则和回传比例
12. Apple Ads App 不支持创建 XAD 传统归因策略和回传策略，仅用于内部归因沉淀和报表分析

### 1.3 本次调整范围
| 模块 | 本次处理 |
| --- | --- |
| 事件中心关联口径 | 仅补充归因和回传引用事件时的事件类型、筛选规则和字段来源，不调整事件中心页面 |
| 归因配置 | 调整事件口径，明确触发事件和媒体触点事件的配置关系 |
| 归因 / 再归因日志 | 不新增字段，仅做必要命名口径调整 |
| Apple Ads 归因解析事件 | 客户服务端通过 AdServices / AdAttributionKit 解析 Apple 返回结果后，经 Kafka 同步至 XAD，用于内部归因沉淀、用户旅程串联和 Apple Ads 报表分析 |
| Apple Ads App 业务事件 | 客户系统通过 Kafka 同步 Apple Ads App 激活、注册、开户、交易等业务事件，用于效果分析和报表统计 |

### 2.3 “媒体触点事件”命名变更
本次统一将原“媒体监控事件”调整为“媒体触点事件”

变更说明：

1. 原“媒体监控事件”统一更名为“媒体触点事件”
2. 原“当用户发生 xxxx 行为时”中的 xxxx 事件，本质为媒体触点事件
3. 前端字段可继续展示为“当用户发生”，但字段说明需明确选择对象为媒体触点事件
4. 媒体触点事件包括但不限于：
    - 监测事件
    - 投放链接事件
    - 短链事件
    - 中转页事件
    - 媒体 callback 事件
    - 媒体点击事件
    - 媒体曝光事件
    - 媒体激活事件
5. 日志中的“命中媒体事件”建议同步调整为“命中媒体触点事件”
6. 回传策略中的“回传媒体事件”不属于媒体触点事件，它表示最终回传给媒体的目标事件

### 用户属性混合归因
归因系统支持基于以下三类用户属性进行混合归因：

1. **用户标识类**  
包括用户设备 ID 及媒体用户标识符，例如 OAID、IDFA、IMEI、CAID、Android ID、Click ID、Request ID 等。
2. **IP 类**  
包括 IPv4、IPv6、通用 IP 及媒体支持的 IP 加密值。
3. **GPS / 定位类**  
包括经纬度、加密经纬度、城市编码及地域编码等定位信息。

用户需根据不同媒体实际支持的监测链接宏参数，在归因条件的「用户属性参数」中选择需要参与匹配的字段。只有已选择并写入监测链接的宏参数，才参与后续归因判断。

#### 匹配规则
同一归因条件下配置的用户属性参数采用 **OR 匹配逻辑**。

任意一个已配置的用户属性参数匹配成功，即视为用户属性匹配通过，可完成归因；不要求用户标识、IP 和 GPS 等参数同时匹配。

示例：

用户配置了 OAID、Click ID、IP 和 GPS 四个用户属性参数，归因时只要其中任意一个参数与业务事件中的对应字段匹配成功，即判定归因成功。

#### 补充规则
+ 未配置的用户属性参数不参与归因判断。
+ 参数为空或未获取到时，当前参数视为未匹配，并继续判断其他已配置参数。
+ 当全部已配置参数均未匹配时，归因失败。
+ 明文与加密字段需按照相同格式进行匹配，不支持明文值与 MD5、SHA1 等加密值直接比较。
+ IPv4、IPv6、经纬度及地域编码应按照媒体实际返回格式进行匹配，不同数据类型之间不进行转换匹配。
